# AI Context
- Summary: Adds ImageMagick visual-regression diffing against committed goldens, greenfield QML logic tests, and extends CI to run in an Arch container.
- Keywords: visual, regression, goldens, qml, logic, tests, arch, container

# Problem
- There is no automated way to catch an unintended visual change; every regression is caught by eye or not at all.
- `qmltestrunner` is present but unused; pure logic (e.g. `ShellConfig._normEntry`, accent resolution) has no test coverage.
- `ci.yml` only lints bash/py/JSON today and has a placeholder for Quickshell CI "once an image is available," so nothing renders or tests QML in CI.

# Scope
- In:
  - ImageMagick `compare` against committed golden images, cropped to component, with frozen inputs (fixed theme, static wallpaper, hidden clock) to beat render nondeterminism
  - Golden images generated by the same headless path as item_067 (pixman software-render drift otherwise breaks diffing)
  - Greenfield QML logic tests via `qmltestrunner` targeting pure logic, extracting to plain JS where a singleton can't load outside Quickshell
  - CI extension: an Arch container job running `qmlformat --check` -> `qmllint` -> `qmltestrunner` -> headless render smoke -> visual diff (uploads diff.png on failure)
- Out:
  - The headless render harness and state-driving mechanics themselves (item_067)
  - AI persona-tester logic and the verify-before-done workflow (item_069)

# Acceptance criteria
- AC1: A visual regression in a themed component is caught by an ImageMagick diff against its golden and fails CI.
- AC2: At least one pure-logic QML unit (e.g. `ShellConfig._normEntry`) has a passing `qmltestrunner` test.
- AC3: The Arch container CI job runs lint -> logic tests -> headless render smoke -> visual diff end to end and uploads a diff artifact on failure.
